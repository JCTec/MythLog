# Effort: On-demand design asset pipeline in CI

Read this whole prompt before starting. Work on a new branch off `main`, named
`ci/design-asset-pipeline`. Commit after each phase completes and its gate
passes. Never push. Never weaken, skip, or delete an existing test or gate to
make something pass. If you are blocked for more than two attempts on the same
problem, stop, write `BLOCKED.md` at the repository root describing exactly what
you tried and why it is stuck, and move to the next independent phase rather
than guessing.

## Goal

Trigger one GitHub Actions workflow by hand, wait, then download a zip
containing every marketing and store asset MythLog needs — built from the **real
app**, not from mockups. No local image tooling, no hand-editing, no scratch
scripts.

## Why this is being built

Every file in `DesignAssets/` today — the App Store screenshots, the hero art,
the logo, the icon set, the privacy PDF — was generated by ad-hoc Python
scripts that were never committed. They do not exist in this repository. The
assets cannot be regenerated, cannot be reviewed, and cannot be corrected
without redoing the work from scratch. Worse, the "app window" visible in the
current App Store screenshots is a **hand-drawn mockup**, not a real screenshot,
because the machine that produced it could not run macOS.

Two governing principles:

**REAL PIXELS ONLY.** Anything that depicts the app must be a genuine screen
capture of MythLog running. No redrawn window chrome, no simulated timelines, no
invented UI. If a real capture cannot be produced, the build fails — it does not
fall back to a mockup. Apple rejects screenshots that are not the actual app
(guideline 2.3.3), so a silent mockup fallback is a submission risk, not a
cosmetic one.

**DETERMINISTIC AND COMMITTED.** Every asset is produced by code in this
repository. Running the pipeline twice on the same commit produces
byte-identical output. No step depends on a font, tool, or file that only exists
on one machine.

## Phase 1 — Bring asset generation into the repository

Nothing else in this plan is possible until generation exists as committed code.

Create `tools/assets/` (Python, Pillow) containing a small, readable module per
output family, driven by one entry point (`tools/assets/build.py`) with
subcommands. Add `tools/assets/requirements.txt` pinned to exact versions.

The generators to write:

- **`logo.py`** — the MythLog mark: a capital "M" drawn as a continuous
  timeline polyline over a dark rounded-square field, hollow ring nodes at each
  vertex, and a solid green "chain head" node with a soft glow at the final
  point, sitting on a faint horizontal axis line. Outputs the 1024px master, a
  wordmark lockup (mark + "MythLog"), and an SVG with matching geometry.
- **`appicon.py`** — regenerates `DesignAssets/AppIcon/` from the logo master:
  all ten `.iconset` PNGs plus a packed `.icns`. **The small sizes must use a
  simplified render** — solid polyline, solid end dot, no hollow rings — because
  the detailed mark turns into an illegible smudge at 16 and 32px. Detailed
  render for 128px and up, simplified for 16/32/64. Pack `.icns` for the tag
  types `icp4 icp5 ic07 ic08 ic09 ic10 ic11 ic12 ic13 ic14` and verify the
  result parses back with correct per-chunk sizes before writing it.
- **`frames.py`** — composes a real app screenshot (Phase 2) into a marketing
  frame: dark gradient background with a green glow top-left and a blue glow
  bottom-right, a faint vertical grid, a centered headline and subhead, a small
  accent rule, and the screenshot inset with rounded corners and a soft drop
  shadow. Produces both the App Store screenshots and the README/hero art.
- **`privacy_pdf.py`** — the privacy policy PDF (ReportLab), with the document
  text held in one place so wording changes are a text edit, not a layout edit.

Port the visual language from the existing assets in `DesignAssets/` — same dark
palette, same green and blue accents, same typographic scale. The current files
are the reference for what the output should look like.

### Known traps — do not rediscover these

These bugs were all hit while producing the current assets. Write the code so
they cannot recur, and add a comment where the fix is non-obvious.

- **Alpha compositing.** Drawing a translucent fill directly onto an RGBA canvas
  that is later flattened to RGB silently discards the alpha and produces a
  solid, opaque block. Every translucent panel, card, or grid overlay must be
  drawn onto its own transparent layer and combined with `alpha_composite`.
  Symptom when wrong: a bright white bar where a subtle frosted panel was
  intended, with white text vanishing into it.
- **Text collision.** Headlines, subheads, and any right-aligned footer must be
  measured and auto-shrunk to fit their allotted box. Fixed pixel offsets break
  the moment a string changes length — a long title will overlap the subtitle
  that follows it. Fit text to the space remaining between its neighbors, not to
  a hardcoded x-offset.
- **Overflow.** Any composed UI row must be laid out on an explicit width budget
  that sums to the frame width. Elements positioned by accumulated offsets run
  off the right edge and get clipped.
- **Canvas trim.** Wordmark and logo exports must be trimmed to their content
  bounding box with a fixed padding, not left on an oversized canvas.
- **Fonts.** The current assets use Poppins, which is **not present on macOS
  runners** (it was read from a Linux font path). Vendor the required `.ttf`
  files into `tools/assets/fonts/` and load them by relative path. Poppins is
  SIL Open Font License, so redistribution is permitted — include the license
  file alongside it. Never resolve a font by system name or absolute path; that
  is the single most likely cause of a pipeline that works locally and silently
  renders wrong in CI.

**Gate:** `python3 tools/assets/build.py all --out /tmp/assets1` and again to
`/tmp/assets2`, then confirm the two trees are byte-identical. Confirm the
regenerated icon set and logo are visually equivalent to what is in
`DesignAssets/` today.

## Phase 2 — Capture real screenshots of the running app

This is the highest-risk phase. Do it after Phase 1 and commit it separately.

Add `scripts/capture-screenshots.sh` that:

1. **Builds the app unsandboxed.** Use `MYTHLOG_DISTRIBUTION=developer-id` via
   `scripts/package-release.sh`. The App Store shape cannot launch under an
   ad-hoc signature with no provisioning profile — the kernel SIGKILLs it — so a
   sandboxed build here will never produce a screenshot. This is settled; do not
   spend time re-testing it.
2. **Seeds a realistic ledger.** An empty timeline makes a bad screenshot. Build
   a fixture with a believable spread of events across the visible window — lock,
   unlock, sleep, wake, app launches, file changes, a heartbeat, and at least one
   warning-severity and one critical-severity event so the severity styling is
   visible. Prefer driving `mythlogctl` (`default-config`, `init-secret`,
   `emit-log`) over hand-writing ledger JSON, so the fixture exercises the real
   append path and stays valid as the schema evolves. Use **fixed timestamps**
   relative to a pinned base time so captures are reproducible and the axis
   labels do not shift between runs.
3. **Launches the app, waits for it to finish rendering, and captures.** Capture
   the window with `screencapture -o -l <windowid>` (window ID via
   `CGWindowListCopyWindowInfo`, or `-R` with a known frame). Set the window to a
   fixed size first so output dimensions are stable. Capture at 2x for Retina
   output.
4. **Captures more than one state.** At minimum: the default timeline, a
   filtered/zoomed view with the inspector open, and the ledger-verified state.
   Each becomes a different store screenshot.
5. **Fails loudly.** If no window appears, if the capture is empty, or if the
   image is uniformly one color (a common symptom of capturing before the window
   is drawn), exit non-zero with a clear message. Never emit a placeholder.

**Validate the GUI assumption early.** Whether a GitHub-hosted macOS runner can
launch a normal `.app` and capture its window is the one thing in this plan that
cannot be confirmed by reading code. Before building the rest of Phase 2, push a
throwaway workflow that launches the app and runs `screencapture`, and look at
the artifact. If a window cannot be captured on the hosted runner, **stop and
write `BLOCKED.md`** rather than working around it with a mockup — record what
failed and note the fallback options (a self-hosted runner on the developer's
own Mac, or keeping capture local while CI does composition only). Do not
silently degrade to drawn UI.

**Gate:** the script produces real PNGs of the app locally, at the expected
dimensions, with visible timeline events.

## Phase 3 — Compose the store assets

Wire Phase 2's captures into Phase 1's `frames.py` to produce:

- **App Store screenshots**, 2560x1600 (16:10), which is a size Apple accepts
  for macOS. Produce five, ordered so the first one alone communicates the
  product. Every one must show the real app in use — not a title card, not a
  splash screen (guideline 2.3.3).
- **README / hero art** at the existing `DesignAssets/Branding/` dimensions.
- **A Setapp-shaped icon variant**: 1024x1024 with the artwork inset inside an
  824x824 frame, i.e. a 100px margin on all sides, exported as `AppIcon.png`.
  Setapp requires this specific inset and that exact filename; the standard
  edge-to-edge macOS icon does not satisfy it.

Headline and subhead strings must come from a single data file
(`tools/assets/copy.yml` or similar), not be embedded in the layout code, so
marketing wording can change without touching rendering. Seed it from the
current text in `DesignAssets/AppStore/metadata.md`.

**Gate:** all outputs land in the expected sizes and no text overlaps, is
clipped, or collides with a frame edge. Inspect every generated image before
declaring the phase done — these are the exact failure modes listed in Phase 1.

## Phase 4 — The workflow

Add `.github/workflows/design-assets.yml`:

- **`workflow_dispatch` only.** No push or PR trigger — this exists to be run by
  hand, and macOS runner minutes on a private repository bill at 10x.
- Inputs: which families to build (`all`, `screenshots`, `icons`, `logo`,
  `privacy`), defaulting to `all`.
- Runs on `macos-latest`, consistent with `ci.yml` (its comment explains why the
  image is not pinned — respect that reasoning).
- Steps: checkout, install Python deps from the pinned requirements file, build
  the app, capture screenshots, compose assets, then upload **one artifact**
  containing the full `DesignAssets`-shaped tree so it can be unzipped straight
  over the repository folder.
- Name the artifact with the run number and short SHA so successive runs are
  distinguishable.
- Do **not** commit assets back to the repository automatically. The developer
  reviews the images first, then copies in what they want.

**Gate:** `ruby -e 'require "yaml"; YAML.load_file(".github/workflows/design-assets.yml")'`
parses, and `./scripts/check-repository-metadata.sh` still passes.

## Phase 5 — Documentation and cleanup

- Write `DesignAssets/README.md` (replacing the current one if thin): what each

  regenerate locally.
- Note in `docs/RELEASING.md` that store assets are produced by this workflow.
- If `scripts/` still contains anything superseded by `tools/assets/`, remove it

Write `HUMAN_CHECKLIST-ASSETS.md` at the repository root with the steps only a

- Confirm the App Store screenshots show the real app and would satisfy

- Check the icon at actual size in Finder, in the Dock, and in the menu bar.
